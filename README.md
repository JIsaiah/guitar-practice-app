# 作品紹介:ギター練習デスクトップアプリ(仮称)

> **開いて、弾くだけ。** ― ギターの練習に必要なものだけを、1つの画面に。

## 30秒で分かる、この作品

| | |
| --- | --- |
| **誰のために** | PCでギターの音を出して練習している人。プラグインやDAWに詳しくなくていい |
| **何を解決するか** | 練習のたびに、音作りのソフト・YouTube・タブ譜ソフトを行き来し、設定に時間を取られる |
| **どうやって** | 音作り・音源・タブ譜・メトロノーム・チューナーを1画面にまとめ、曲ごとに「セッション」として丸ごと保存する |

## なぜ作ったのか

ギターの練習中は、両手が楽器で塞がっています。それなのに練習の環境は、音を作るソフト、お手本の動画、タブ譜のソフトがばらばらで、ウィンドウを行き来するたびに練習が止まっていました。

既存のツールは、どれも高機能です。ただ、ただ練習したい人にとっては、できることが多すぎて、何をすればいいか分からなくなります。

**「考えずに、すぐ弾き始められる練習環境」がほしい**。自分自身のこの不満が、開発の出発点です。

## 既存ツールとの違い

| | 何のためのツールか | この作品が取り入れたもの | 取り入れなかったもの |
| --- | --- | --- | --- |
| Guitar Pro 8 | タブ譜の作成・MIDI再生 | タブ譜の表示、音源との同期 | 高度な譜面作成 |
| Reaper(DAW) | 音楽制作 | プラグインで楽器の音を出す部分 | 録音、作曲、ミックス |
| スマホアプリ | 手軽な練習 | ― | 画面と端子の制約で、音出し・音源・タブ譜を同時に使えない |
| Webアプリ | 手軽な練習 | ― | 遅延と音質。結局タブを複数開く |

### あえて作らなかったもの
録音、作曲、ミックス、MIDIの打ち込み、YouTube以外の配信サービス。
**「練習に要らないものを持たない」こと自体が、この作品の設計方針です。**

## ブースで触ってほしいところ

1. **セッションを開いて、3クリックで弾き始める** ― 音源・音色・譜面・速度が、前回の状態のまま戻ります
2. **YouTubeの速度を落とすと、タブ譜とメトロノームが付いてくる** ― YouTube側の画面で速度を変えても、アプリが追従します
3. **苦手な小節だけをループし、速度を落として練習する** ― 操作はマウスのホイールだけ
4. **チューナーで合わせて、すぐ弾く** ― プラグインの知識がなくても、内蔵の音色で良い音が出ます

## 技術的なチャレンジ(エンジニアの方へ)

### 1. リアルタイム音声処理
ギターの音は、オーディオスレッドの中で処理を完結させます。このスレッドでは、メモリ確保・ロック・ファイル操作を禁止する規約を設け、他のスレッドとはロックフリーの仕組みだけで通信します。C++ではコンパイラがこれを守ってくれないため、設計段階で規約として明文化しました。

### 2. 2つの「時計」を合わせる
ローカルの音源ファイルと、YouTubeの動画では、再生位置の基準(時計)が違います。
- ローカル音源: アプリが再生するので、サンプル単位で正確に位置が分かる
- YouTube: 外部のプレイヤーなので、位置を問い合わせて推定するしかない

音源ごとに基準の時計を切り替え、タブ譜のカーソル・メトロノーム・ループを、その時計に追従させる設計にしました。

### 3. ネイティブとWeb技術の組み合わせ
音声処理はC++(JUCE)で、タブ譜の描画とYouTubeは、別プロセスのWebView2の中で動かします。WebViewが重くなっても、音は止まりません。

### 4. プラグインのホスト
内蔵の音色(NAM)と、ユーザーが持っているVST3プラグインを、同じ「音色スロット」として扱います。状態はセッションごとに保存・復元します。

## 設計の進め方

要件定義 → 技術検証(PoC)→ 実装、の順に進め、**判断とその理由を「設計決定記録」として残しています**。いくつか例を挙げます。

- **不確実な技術を、仕様の見直しで消した**: 当初は、ブラウザの音をアプリに取り込む方式を予定していました。最も技術的なリスクが高い部分だったため、要件を見直し、Web音源を操作用のAPIがあるYouTubeに限定しました。リスクがなくなっただけでなく、速度変更やタブ譜との同期もできるようになりました
- **目標値を、実体験から決めた**: 遅延の目標は、作者が実際に違和感なく弾けている設定(48kHz/バッファ256で25.8ms)を基準にしました
- **ライセンスを調べてから技術を選んだ**: 使用するライブラリのライセンス(AGPL、MIT、MPLなど)を整理し、将来の公開に備えています
- **ターゲットを絞り直した**: 「PCでギターの音を出せるが、プラグインには詳しくない人」に絞ったことで、内蔵の音色を主役にし、専門的な設定は詳細設定の奥に移しました
