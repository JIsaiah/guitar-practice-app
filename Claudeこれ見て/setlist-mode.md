# セットリストモード 実装仕様書

> ライブに向けて複数曲を通しで練習するための機能。
> この文書はClaude Codeに実装を依頼するための仕様書です。上から順に「フェーズ」単位で実装し、各フェーズの完了条件を満たしてから次に進んでください。
> 【仮決め】と書いた項目は、作者がまだ最終確認していない初期値です。実装はその内容で進め、変更しやすい形にしておくこと。

## 0. 前提

- C++20 / JUCE 8 / Windowsのみ
- 優先事項：使いやすさ、低遅延、反応の速さ。**片手・マウス操作だけで完結すること**
- 成功指標：保存済みのものを開いてから弾き始めるまで3クリック以内（セットリストでも守る）
- 依存する機能：**再生開始の遅延（カウントダウン）**。未実装なら、本仕様のフェーズ3で最小限の実装を行う（7章）
- 関連する別機能：音色の自動切り替え（別仕様書）。先読み（6章）は、その機能が入っても動くように「セッションが持つ全音色」を読み込む前提で設計する

## 1. 機能概要

- 一覧画面の上部タブで「セッション」「セットリスト」を切り替える
- セットリストは、セッション一覧と同じ形式のカードで表示する
- セットリスト（親）は、セッション（子）への**参照**を曲順に並べたもの。セッションのデータそのものはコピーしない
- セットリストから開いたときだけ、セッション画面の下部に**セットリスト用メニュー**（進捗、何曲目か、次・前ボタン、次の曲名）を表示する
- 曲が終わると、ユーザーが設定したカウントダウン時間だけ待ち、画面中央にカウントダウンを表示してから、次の曲を自動で再生する
- 曲の切り替えは、次の曲を先読みしておくことで待ち時間なく行う

## 2. 決定事項

| 項目 | 決定内容 |
|---|---|
| 子の持ち方 | **参照方式**。セットリストはセッションIDの並びを持つ |
| 同じ曲の重複 | **許可する**。1つのセットリストに同じセッションを何度でも入れられる |
| 曲の追加方法 | 「追加」ボタン方式（チェックボックス方式は使わない。重複追加ができないため） |
| セッション一覧から開いた場合 | 次・前ボタンを含むセットリスト用メニューは**表示しない** |
| セットリストから開いた場合 | 下部にセットリスト用メニューを表示する |
| ループ・速度 | セットリストの各曲（エントリ）ごとに**専用の設定**を持つ。追加時に初期化され、そこから再調整できる。単体のセッションの設定とは独立 |
| ループ・速度以外の設定 | 音色、ミキサー、オフセットなどは元のセッションと共有。セットリストから開いて変更すると、元のセッションに保存される |
| 曲間 | 設定画面の「再生開始前の待ち時間」をそのまま使い、画面中央にカウントダウンを表示 |

## 3. データモデル

### 3.1 セッションID

- セッション（.gppractice）に `sessionId`（UUID文字列）を追加する
- 既存のセッションにIDが無い場合は、読み込み時に生成して保存し直す（マイグレーション）
- セッションファイルにフォーマットのバージョン番号が無ければ、この機会に追加する

### 3.2 セッションライブラリ

- 起動時にセッション保存フォルダを走査し、`sessionId → ファイルパス` の対応表を作る
- セッションの保存・削除・名前変更時に対応表を更新する
- これにより、ファイルを移動・改名してもセットリストのリンクが切れない

### 3.3 セットリストファイル

拡張子は `.gpsetlist`（JSON）。

```json
{
  "formatVersion": 1,
  "setlistId": "UUID",
  "name": "11月ライブ",
  "createdAt": "ISO8601",
  "updatedAt": "ISO8601",
  "entries": [
    {
      "entryId": "UUID",
      "sessionId": "UUID",
      "overrides": {
        "speed": 1.0,
        "loop": { "enabled": false, "startSec": 0.0, "endSec": 0.0 }
      }
    }
  ]
}
```

- `entryId` はエントリごとに一意。**同じセッションが複数回入っても区別できるように**、選択・並び替え・削除・専用設定はすべて `entryId` で扱う
- 曲順は配列の順番
- `overrides` はエントリ専用のループ・速度設定。単体セッションの設定とは完全に独立

### 3.4 専用設定の初期化

エントリ追加時の `overrides` の初期値：

- 速度：1.0（原速）
- ループ：無効

【仮決め】ループ範囲の時刻は、単体セッションのループ範囲をコピーしておく（無効状態のまま）。有効にしたときに範囲を一から作り直さずに済むため。

### 3.5 開き方のコンテキスト

セッション画面は、どこから開かれたかを表す次の情報を受け取る。「次の曲」はセッション自体ではなく、このコンテキストで決まる。

```cpp
struct SessionOpenContext
{
    enum class Kind { Standalone, Setlist };
    Kind kind = Kind::Standalone;
    juce::String setlistId; // Setlist のときのみ
    juce::String entryId;   // Setlist のときのみ
};
```

- `Standalone`：単体セッションの設定（ループ・速度）を使う。セットリスト用メニューは表示しない
- `Setlist`：ループ・速度はエントリの `overrides` を使う。それ以外はセッションの設定を使う

### 3.6 設定の保存先

| 設定 | Standaloneで開いたとき | Setlistで開いたとき |
|---|---|---|
| 速度 | セッションに保存 | エントリの`overrides`に保存 |
| A-Bループ | セッションに保存 | エントリの`overrides`に保存 |
| 音色・ミキサー・オフセット・その他 | セッションに保存 | セッションに保存 |

- Setlistで開いているとき、ループと速度のコントロールには「セトリ専用」の小さな表示を付け、単体セッションとは別の設定であることがわかるようにする

## 4. 一覧画面

### 4.1 タブ

- 上部に「セッション」「セットリスト」のタブ。クリックで切り替え
- 最後に開いていたタブを記憶し、次回起動時に復元する

### 4.2 セットリストのカード

- セッションのカードと同じ見た目・サイズ
- 表示：名前、曲数、合計時間（長さが分かる曲の合計。不明な曲があれば「約」を付ける）
- カード上の大きな「通しで再生」ボタン：1曲目から開始（**一覧画面のタブ → このボタンの2クリックで再生開始**）
- カードのクリックで展開し、子（曲順）を表示する

### 4.3 展開時（曲順の編集）

- 各行：曲順の番号、セッション名、長さ、専用設定が初期値から変わっていれば印（例：速度80%）
- 行のクリック：その曲からセットリストを開始
- ドラッグで並び替え
- 右クリックメニュー：「セットリストから外す」（セッション自体は削除しない）、「元のセッションを単体で開く」
- **リンク切れ**（参照先のセッションが無い）の行はグレー表示にし、「見つかりません」と表示。右クリックで外せる

### 4.4 曲の追加

- 展開したセットリストの末尾に「＋ 追加」ボタン
- クリックするとセッション選択パネルを開く。パネル内のセッションを**クリックするたびに末尾に1件追加**される（同じものを複数回クリックすれば重複して追加される）
- パネルは開いたままにし、続けて追加できる。「閉じる」で終了
- 追加した直後、パネル内の該当セッションに「追加済み×2」のように回数を表示する

### 4.5 セットリストの作成・削除

- セットリスト一覧の先頭に「新しいセットリスト」カード
- 作成時の名前は「セットリスト 1」のように自動で付け、あとから変更可能（名前変更だけはキーボード入力を許可する）
- 削除は右クリックメニューから。確認ダイアログを出す。セッション自体は削除しない

### 4.6 セッション削除時

- セッション一覧からセッションを削除するとき、そのセッションを参照しているセットリストがあれば、確認ダイアログに「○件のセットリストで使われています」と表示する
- 削除後、該当エントリはリンク切れとして残す（自動では消さない）

## 5. セッション画面（Setlistで開いたとき）

### 5.1 下部のセットリスト用メニュー

- セットリスト名
- 「3 / 8」：今何曲目か
- 進捗バー：セットリスト全体の進み具合。【仮決め】曲数ベース（終わった曲数＋今の曲の再生位置の割合）で計算する。合計時間ベースだと、長さ不明の曲がある場合に計算できないため
- 「前の曲」「次の曲」ボタン（大きなヒットボックス）
- 次の曲名（最後の曲なら「最後の曲です」）
- 「通し再生を止める」ボタン：今の曲を止め、セットリストの自動送りを止める

### 5.2 次・前ボタンの動き

- 「次の曲」：今の曲を止め、カウントダウン → 次の曲を再生
- 「前の曲」：同様に前の曲へ
- 最初の曲で「前の曲」、最後の曲で「次の曲」は無効表示
- リンク切れのエントリは飛ばす
- 【仮決め】手動で移動したときもカウントダウンを入れる（ボタンを押してからギターに手を戻す時間が必要なため）

## 6. 曲の切り替えを軽くする（先読み）

### 6.1 方針

**今の曲を再生している間に、次の曲をバックグラウンドで準備しておき、曲の終わりで差し替えるだけにする。** カウントダウンの時間も準備に使える。

### 6.2 先読みする内容

1. セッションファイルの読み込みと解析
2. ローカル音源ファイルを開き、再生できる状態にする（全体をデコードしてメモリに載せるのではなく、ストリーミング再生の準備まで）
3. タブ譜ファイルの解析
4. VST3プラグインの生成と状態の復元、`prepareToPlay`。音色が複数ある場合は全音色
5. Web音源（YouTubeなど）の場合：【仮決め】2つ目のWebViewは使わず、カウントダウン開始と同時に今のWebViewで次の動画を読み込む。WebViewを2つ持つとメモリを大きく消費するため

### 6.3 スレッドの扱い

- ファイルの読み込み・解析はワーカースレッド（`juce::ThreadPool`）で行う
- VST3プラグインの生成は、プラグインによってはメッセージスレッドが必要なため、`AudioPluginFormatManager::createPluginInstanceAsync` を使い、メッセージスレッドを長時間ブロックしない
- **オーディオスレッドでは、メモリ確保・ファイルI/O・ロックをしない**。準備ができたオーディオ処理系への切り替えは、ポインタの差し替え（アトミック）だけで行う
- 前の曲の処理系の破棄は、オーディオスレッドが使わなくなったことを確認してから、メッセージスレッドかワーカースレッドで行う（オーディオスレッドで`delete`しない）

### 6.4 先読みの範囲

- 先読みするのは「次の1曲」だけ（メモリとCPUの負荷を抑えるため）
- 今の曲を開いた直後に、次の曲の先読みを開始する
- 曲順の変更、手動の次・前の移動があったら、先読みを破棄して正しい次の曲で作り直す

### 6.5 間に合わなかった場合

- カウントダウン終了時点で先読みが終わっていなければ、画面中央に「読み込み中…」と表示し、完了後すぐに再生する
- 先読みに失敗した場合（プラグインが見つからないなど）は、通常どおりセッションを開いたときと同じエラー表示を出し、自動送りを止める

## 7. 曲の終わりとカウントダウン

### 7.1 再生状態

再生の状態に「カウントダウン中」を追加する。

```
Stopped → CountingDown → Playing → (曲の終わり) → CountingDown(次の曲) → Playing → …
```

- カウントダウンの秒数は、設定画面の「再生開始前の待ち時間」を使う（0秒ならすぐに次の曲へ）
- カウントダウンは、音源とタブ譜のずらし調整（オフセット）とは別物。カウントダウン終了後に、音源とタブ譜を同じ時計で同時に開始する。オフセットの計算にカウントダウンの時間を混ぜないこと

### 7.2 画面中央のカウントダウン表示

- 画面中央に大きな数字（3、2、1）を表示。離れた位置からでも読める大きさ
- 数字の下に次の曲名を表示する
- 表示中に数字をクリック：カウントダウンを飛ばしてすぐ開始
- 「通し再生を止める」ボタンで中止できる
- カウントダウンのタイマーはメッセージスレッドの`juce::Timer`で十分（秒単位で、サンプル単位の精度は不要）

### 7.3 「曲の終わり」の判定

| 音源 | 判定方法 |
|---|---|
| ローカル音源 | 音源の終端に達したとき |
| YouTube | 埋め込みプレーヤーの再生終了イベント |
| 終了を検知できない音源（Spotifyなど） | 自動送りしない。セットリスト用メニューに「この曲は自動で次に進みません」と表示し、「次の曲」ボタンで進める |

- タブ譜と音源の長さが違う場合は、**音源の終わり**で判定する
- エントリ専用設定でA-Bループが有効な場合、曲は終わらないので自動送りされない。【仮決め】ループ有効中はセットリスト用メニューに「ループ中のため自動で次に進みません」と表示する

### 7.4 最後の曲が終わったとき

- 「セットリスト終了」と画面中央に表示し、「最初から」「一覧に戻る」の大きなボタンを出す
- 【仮決め】セットリスト全体のループ再生は今回は実装しない

## 8. Web音源の自動再生

- 埋め込みブラウザ（WebView2）は、ユーザーのクリックなしでの動画の自動再生をブロックすることがある
- セットリストの2曲目以降はクリックなしで再生を始めるため、WebView2の自動再生ポリシーを許可する設定が必要か、**フェーズ1の前に検証すること**
- 許可できない場合は、Web音源の曲ではカウントダウン後に「クリックで再生」を表示する

## 10. テスト（JUCE UnitTest）

1. **JSONの往復**：セットリストを保存→読み込みして内容が一致する
2. **重複**：同じセッションを3回追加し、それぞれ別の`entryId`を持ち、個別に並び替え・削除・専用設定の変更ができる
3. **専用設定の独立**：Setlistコンテキストで速度を変えても、単体セッションの速度は変わらない。逆も同じ
4. **共有設定**：Setlistコンテキストで音色の設定を変えると、単体セッションにも反映される
5. **リンク切れ**：存在しない`sessionId`のエントリを、次・前の移動と自動送りで飛ばす
6. **端の処理**：最初の曲で「前」、最後の曲で「次」が無効
7. **マイグレーション**：`sessionId`の無い古いセッションを読み込むとIDが付与され、2回目の読み込みでも同じIDになる
8. **カウントダウン**：待ち時間0秒ですぐ次へ進む。カウントダウン中のスキップ・中止が正しく状態遷移する
9. **先読みの作り直し**：再生中に曲順を変えると、先読みが正しい次の曲に切り替わる

## 11. 実装フェーズ

| フェーズ | 内容 | 完了条件 |
|---|---|---|
| 0 | WebView2の自動再生の検証（8章） | クリックなしでYouTubeを再生できるか、できないならその代替方針が決まっている |
| 1 | セッションID、SessionLibrary、Setlistのデータモデルと保存 | テスト1・2・7が通る |
| 2 | 一覧画面のタブ、セットリストのカード、展開表示、追加パネル、並び替え、削除 | マウスだけでセットリストを作成し、重複を含めて曲を追加・並び替え・削除できる |
| 3 | SessionOpenContext、PlaybackSettingsResolver、CountdownController（未実装なら再生開始の遅延もここで） | テスト3・4・8が通る。セットリストから開くとループ・速度が専用設定になる |
| 4 | SetlistPlayer、下部メニュー、画面中央のカウントダウン、曲の終わりの判定、自動送り（先読みなし） | ローカル音源で、曲の終わり → カウントダウン → 次の曲の再生が通しで動く。テスト5・6が通る |
| 5 | SessionPreloader（先読み） | 次の曲への切り替えで、カウントダウン終了から再生開始までの待ちが体感で無い。テスト9が通る |
| 6 | Web音源の自動送り、リンク切れ表示、セッション削除時の確認、セットリスト終了画面 | 7.3・7.4・4.6の動きがすべて確認できる |

**フェーズ4とフェーズ5を分ける理由**：先に先読みなしで自動送りの流れを完成させ、そのあと先読みを差し込む。先読みはスレッドをまたぐため不具合が出やすく、流れと分けておくと原因を切り分けやすい。

## 12. 注意事項

- オーディオスレッドでは、メモリ確保・ファイルI/O・ロック・プラグインの生成と破棄をしない
- 片手・マウスだけで、作成から通し再生まで完結すること（名前の入力を除く）
- セットリストから外す・セットリストを削除する操作で、**セッション自体は絶対に削除しない**
- 【仮決め】の項目は、定数や設定値としてまとめ、後から変えやすくしておく
