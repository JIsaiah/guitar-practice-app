# 実装指示:デザイン基盤(2026-10-31の決定分)

> Claude Code向けの作業指示です。背景と詳細は`docs/設計書.md`(v0.7)の**4.4〜4.10**と**5.1**を参照してください。

---

## 1. 今回決まったこと(要約)

| 項目 | 決定 |
| --- | --- |
| コンセプト | 「リハーサルスタジオ」。ライト=昼のスタジオ、ダーク=夜のスタジオ。土台は青みのある寒色グレー、アクセントは琥珀色の1色だけ |
| 画面の描き方 | **セッション一覧と設定はJUCE(ネイティブ)**、**練習画面はWebView2(HTML/CSS)** |
| デザインの決め方 | すべての画面をまずHTML/CSSで試作し、Impeccableで見た目を決める。試作を「見た目の正本」とし、一覧と設定はJUCEに移植する |
| WebViewの起動 | 起動画面(一覧)はネイティブで即表示。**一覧を表示した直後に、裏でWebViewを1つだけ準備**し、以後は作り直さずに使い回す |
| 動き | 起動時、一覧のカードを上から順にフェードイン(1枚0.15〜0.2秒、全体で約0.3秒)。動きの途中でもクリックできる。Windowsの「アニメーション効果」がオフなら省く |
| テーマ | 既定はWindowsのテーマに従う。手動でも切り替えられる。テーマは「トークンの組」として追加できる構造にする |

優先順位は変わらず「① 使いやすさ ② 低遅延 ③ 反応の速さ」。**デザインのために、起動や操作を遅くしてはいけない。**

---

## 2. 守ること(制約)

### 2.1 見た目の表現(HTMLの試作の段階から守る)
JUCEに移植できる表現だけを使う。
- レイアウトは flex と grid で組む
- 影は1つだけ、角の丸みは単純なもの
- `backdrop-filter`、複雑なグラデーション、CSSの`filter`は使わない
- アニメーションは`opacity`と`transform`だけ。0.15〜0.25秒程度
- 真っ白(`#FFFFFF`)と真っ黒(`#000000`)は使わない。文字のコントラスト比は4.5:1以上

### 2.2 速さ
- HTMLは重いフレームワークを使わない(素のHTML/CSS/JS、または十分に軽いもの)
- フォント・スクリプト・画像はすべて同梱する。**ネットから読み込まない**
- アニメーションで操作を待たせない

### 2.3 既存の規約
- オーディオスレッドの規約(メモリ確保・ロック・ファイル操作の禁止)は、UIの作業でも変わらない。UIからオーディオへは、アトミック変数かロックフリーのキューだけで渡す

## 3. 作業

順番に進める。**T1〜T3は音声のPoC(PoC-0〜2)と並行してよい。T4・T5はPoC-0(開発環境)の完了後に行う。**

### T1. デザイントークン
**作るもの**
- `design/tokens.json`: 色・文字・余白・角の丸み・影・動きの値を、テーマ(`light`、`dark`)ごとに持つ
- 生成スクリプト(言語は任せる): `tokens.json`から次の2つを生成する
  - `design/generated/tokens.css`: CSSの変数。`:root[data-theme="light"]`と`:root[data-theme="dark"]`、およびOSの設定(`prefers-color-scheme`)に従う既定
  - `src/ui/DesignTokens.h`: C++の定数(`juce::Colour`など)。テーマごとに値の組を持ち、実行時に切り替えられる形
- 生成物はコミットする。ビルド時の自動生成にするかは任せる(手順をREADMEに書く)

**色の初期値**

| トークン | light | dark |
| --- | --- | --- |
| `background` | `#EEF2F6` | `#1D2025` |
| `surface` | `#F8FAFC` | `#272B32` |
| `text` | `#1E2630` | `#E3E7EC` |
| `textMuted` | `#5A6573` | `#9AA3AE` |
| `accent` | `#B45309` | `#F0A43A` |

- ライトの`accent`は背景に対して4.5:1にわずかに届かない。**塗りと大きな文字にだけ使う**
- それ以外(余白・文字サイズ・影など)の値は、T2で試作しながら決めてよい
- フォントは未決。当面は`Yu Gothic UI`と`Segoe UI`で仮置きし、トークン経由で差し替えられるようにする。数字には等幅の数字(tabular figures)を使う

**完了条件**
- スクリプトを実行すると、2つのファイルが生成される
- 生成したCSSとC++の色の値が一致している
- 文字と背景のコントラスト比を計算し、4.5:1以上であることを確認する(結果を報告する)

### T2. HTMLの試作
**作るもの**: `design/prototype/`に、次の4画面の静的なHTML。すべて`tokens.css`を使う。

| 画面 | 内容 |
| --- | --- |
| `session-list.html` | 「新しいセッション」ボタン、セッションのカード、設定(歯車)だけ。カードには曲名、音源の種類(ファイル/YouTube)、最後に練習した日、前回の速度。最後に練習した順。起動時のフェードイン |
| `practice.html` | タブ譜の領域(仮の画像か枠)が主役。YouTubeの枠(任意)。下部に再生/停止、速度、BPM、TAP、A-Bループ、チューナー。横に音色の切り替えとミキサー(音源・ギター・メトロノーム) |
| `new-session.html` | 音源(ファイル/YouTubeのURLを貼り付け)、タブ譜(任意)、音色、BPMの確認、「練習を始める」 |
| `settings.html` | オーディオデバイス、VST3、テーマ、そのほかの設定 |

- 文言は日本語。ダミーデータを数件入れる
- ライト/ダークの切り替えボタンを置く(確認用)
- 2.1の制約を守る

**完了条件**
- ブラウザで4画面が表示でき、ライトとダークの両方で崩れない
- ネットに接続していなくても表示できる

### T3. Impeccableでデザインを決める(作者と一緒に行う)
1. Impeccableを公式の手順で導入する
2. 初回セットアップ(teach-impeccable)で、`docs/impeccable_デザイン前提.md`の内容を渡し、`.impeccable.md`をリポジトリの直下に作る
3. T2の試作に、`critique`などのコマンドをかけて改善する。**提案が2.1の制約に反する場合は、制約を優先する**
4. 決まった値は`tokens.json`に戻し、T1のスクリプトで再生成する

**完了条件**: 作者が4画面の見た目を承認する

### T4. セッション一覧のネイティブ実装(PoC-0の完了後)
**作るもの**: 承認された`session-list.html`を、JUCEのComponentで再現する。
- 色・余白などは`DesignTokens.h`だけを使う。数値を直接書かない
- レイアウトはJUCEの`FlexBox`か`Grid`で組む
- **起動時のフェードイン**: JUCE 8のアニメーションの仕組みを使い、カードを上から順に表示する(試作と同じ時間・遅れ・動く距離)。**動きの途中でもクリックを受け付ける**
- Windowsの「アニメーション効果」の設定を読み、オフならアニメーションを省く
- テーマ: 既定はWindowsのテーマ設定に従い、手動の切り替えも反映する
- カードをクリックしたら、確認なしで練習画面へ遷移する(練習画面は空の仮画面でよい)

**完了条件**
- 試作と本番のスクリーンショットを並べ、色・配置・文字の大きさが一致している(画像を保存して報告する)
- ライト/ダークの両方で表示できる
- フェードインの途中でカードをクリックしても、遷移できる

### T5. WebViewの先行準備と時間の計測(PoC-3と合わせて行う)
- 一覧を表示した直後に、裏でWebView2を1つだけ生成し、`practice.html`(T2の試作)を読み込んでおく
- 練習画面への遷移時は、準備済みのWebViewを表示するだけにする。アプリの起動中は破棄しない
- ページは`https://`のオリジンで配信する(JUCEのリソース配信、またはWebView2の仮想ホストの機能)。YouTubeの埋め込みエラー(153)を避けるため
- 次の時間を計測し、ログに出す
  1. アプリの起動から、一覧が表示されるまで
  2. 一覧の表示から、WebViewの準備が終わるまで
  3. カードのクリックから、練習画面が操作できるまで

**完了条件**: 3つの時間を、コールドスタート(PC再起動後の初回)とウォームスタート(2回目以降)で各3回測り、報告する。目標値は、この結果を見て作者が決める
